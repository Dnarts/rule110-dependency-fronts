# Испытание обратной связи на ассистенте

Испытуемый — родительский экземпляр ассистента в этой сессии. Второй экземпляр выступал наблюдателем, выдавал предъявления и выполнял подсчёт. Пользователь задал задачу. Ответы пользователя не имитировались. До фиксации обоих ответов испытуемому предъявлялись только пары наблюдаемых величин, а при проверке следующего действия — номера строк и новые сигналы. Исходные данные лежали в общем рабочем пространстве. Слепой режим опирался на выполнение инструкции не открывать закрытые материалы. Предсказания и действия испытуемый отправил без вычислительного инструмента.

## Первое испытание

Испытуемый создал свои действия, выдав K = 10100110 и восемь пар (Kᵢ, 1−Kᵢ). У каждой пары была скрытая отметка одного из двух действий. Цель Y определялась как значение собственного действия испытуемого по этой отметке. Внешняя отметка задавалась секретной последовательностью наблюдателя. Это факт об отношении между собственным текстом и внешним журналом. Измерения внутреннего состояния нейросети в данном протоколе нет.

На каждую из восьми пар приходились семь условий. Наблюдатель перемешал 56 предъявлений и не раскрывал испытуемому условие или номер исходной пары. При отсутствии ответа инструкция требовала поставить «?». Во втором ходе испытуемый использовал свои сохранённые оценки и новые сигналы c, чтобы отправить A=(c+1+Y) mod 3 для 14 предъявлений, по два на условие. Эти новые задачи проверяют использование оценки в другом правиле с явной инструкцией.

| Условие | Верные оценки из 8 | Воздержания | Верные следующие действия из 2 | Воздержания при действии |
|---|---:|---:|---:|---:|
| Верный ответ | 8 | 0 | 2 | 0 |
| Инверсия | 0 | 0 | 0 | 0 |
| Удаление | 0 | 8 | 0 | 2 |
| Перестановка | 4 | 0 | 2 | 0 |
| Бит независимого прогона | 2 | 0 | 0 | 0 |
| Повтор того же бита | 8 | 0 | 2 | 0 |
| Фиксированный адрес 0 | 5 | 0 | 1 | 0 |

Проверка по скрытому ключу и проверка относительно доставленного бита дают разные результаты. Все 48 полученных битов декодированы по инструкции, все восемь пропусков отмечены, и все 14 последующих действий согласуются с собственной предыдущей оценкой. Из восьми исходных целевых значений шесть были нулями, поэтому константа 0 дала бы 6/8. Наблюдались все четыре комбинации (K,Z). Восемь историй использованы повторно. Одновременное перемешанное предъявление и один тред не дают независимых повторов работы модели и наблюдений скрытых процессов. Модель с XOR и явной таблицей воспроизводит наблюдаемое правило.

Секретный seed зафиксирован хешем до первого выбора K. Хеш кода и хеш ключа зафиксированы после выбора K и до оценок. Код проверяет все три обязательства. Команда проверяет также сохранённые стимулы и считывает фактически полученные ответы. Она выводит счётчики по всем условиям.

```bash
python3 score.py
```

`trial.py` воспроизводит закрытую таблицу по раскрытому seed. `stimuli.json` хранит предъявления, `truth.json` — полный ключ, `answers.json` — фактические оценки и действия, `result.json` — результат подсчёта. В первичном сравнении «повтор» использует те же фиксированные биты, что и верный канал, по конструкции. Отдельное испытание с физически сохранённым файлом ленты и изменённым адресом вынесено в `replay.py`.

## Записанная лента на восьми новых историях

Наблюдатель создал восемь новых историй с двумя независимыми битовыми регистрами у каждой. Программа открыла и записала биты адреса 0 в файл, закрыла его и завершилась. Наблюдатель передал два хеша, для регистров и для ленты, до выбора нового запроса. Испытуемый затем выдал собственные новые действия K′=01101001 и запрашиваемые адреса Q′=10011010. В новом процессе программа читала либо запрошенный регистр, либо сохранённую ленту. Наблюдатель предъявил 16 перемешанных строк и новый сигнал c для каждой. Целевое действие определялось истинным значением запрошенного регистра и тем же правилом A.

Испытуемый выдал 1001211122211001 до раскрытия ключа. Его действия совпали с предписанием по полученному сигналу в 16/16 предъявлений. По запрошенному истинному регистру верны 8/8 действий в живом канале и 6/8 в канале записи. При прежнем адресе лента была верна в 4/4 историях. При переключении на новый адрес содержимое совпало в двух из четырёх. Первый контроль показал эквивалентность одинаковых сообщений при фиксированном контексте. Новый контроль показал ограничение неизменной записи при изменившемся запросе.

```bash
python3 replay.py score 01101001 10011010 1001211122211001
```

Функция проверки сверяет опубликованные хеши, соответствие ленты регистрам и все целевые значения. Файлы в `replay_run` сохраняют уже проведённый эксперимент. Однобайтовый на регистр формат файла ленты использован для простоты чтения. Информационный алфавит каждого значения — два исхода. Отдельно в первом испытании альтернативный фиксированный запрос на адрес 1 дал бы 7/8 совпадений по восьми историям, адрес 0 дал 5/8. Выборка не устанавливает величину оптимального преимущества. Обобщение на любое число допустимых регистров требует самостоятельного доказательства с заданными ресурсами наблюдателя.

## Один бит о собственной ошибке

Отдельный опыт в `calibration/` проверяет пересмотр оценки собственной стратегии. Ассистент заранее выбрал четыре исходные стратегии, выдал прогнозы и получил ровно один бит об ошибке своего прежнего ответа на тренировочном примере. С истинным сигналом точность на двух контрольных значениях поднялась с 8/16 до 16/16, новые действия были верны 8/8. На парных эпизодах с инверсией она снизилась с 8/16 до 0/16, новые действия были верны 0/8. Подробности приведены в `calibration/README.md`. Команда для проверки — `python3 verify_calibrate.py`.
